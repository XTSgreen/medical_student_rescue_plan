# 4.7 对象引用、拷贝与内存管理


写 Python 代码时，常会遇到一些看似诡异的现象：明明只改了一个变量，另一个变量也跟着变了；明明复制了一份列表，修改嵌套元素后原列表也被波及。这些问题的根源都在于 Python 的变量模型与拷贝机制。Python 的变量持有的是对象的引用，对象本身存放在独立的内存空间中。理解引用与拷贝的区别，是写好组合数据类型程序的关键前提。本节将系统讲解对象引用、赋值与拷贝的关系，以及内存管理的基本概念，帮助你避开初学者最容易踩的坑。

## 4.7.1 变量存储的是对象的引用

Python 中变量存储的是对象的**引用**，对象本身存放在内存中独立的区域。可以把变量想象成一个标签，贴在某个对象上。使用 `id()` 函数可以查看对象在内存中的地址，从而验证这一模型。

```python
a = [1, 2, 3]
print(id(a))  # 一串数字，表示对象在内存中的地址

b = a
print(id(b) == id(a))  # True，b 和 a 指向同一个对象
```

这段代码中，`a` 和 `b` 是两个不同的变量名，但它们贴在同一个列表对象上。通过任何一个变量修改对象内部状态，另一个变量都能感知到。Python 的变量更像对象的别名。

## 4.7.2 赋值操作不复制对象

赋值语句 `b = a` 不会创建新对象，只是把 `a` 引用的对象再绑定一个名字 `b`。这种关系称为**别名引用**，`a` 和 `b` 共享同一个对象。

```python
a = [1, 2, 3]
b = a
print(a is b)  # True，is 判断两个变量是否引用同一对象

b.append(4)
print(a)  # [1, 2, 3, 4]，a 也变了
```

`is` 运算符判断两个变量是否指向同一对象，比 `==` 更严格。`==` 比较的是值是否相等，`is` 比较的是身份是否相同。上例中 `b.append(4)` 修改了列表对象本身，由于 `a` 和 `b` 引用的是同一个列表，`a` 自然也反映了这次修改。如果希望 `b` 是一份独立副本，就需要显式拷贝，后面会详细介绍。

## 4.7.3 不可变对象的赋值陷阱

对于**不可变对象**（如整数、字符串、元组），重新赋值会改变变量引用的对象，而不是修改原对象。这一点容易被忽略，导致理解上的偏差。

```python
x = 10
y = x
print(x is y)  # True，初始时引用同一对象

x = x + 1
print(x)  # 11
print(y)  # 10，y 仍引用原对象
print(x is y)  # False，x 现在引用新对象
```

`x = x + 1` 这一行看上去像是把 `x` 增加 1，实际上它创建了一个新的整数对象 11，然后把 `x` 重新绑定到这个新对象。整数本身不可变，没有原地加 1 这回事。`y` 仍然引用原来的 10，所以不受影响。字符串和元组同理，任何看似修改的操作其实都返回了新对象。

## 4.7.4 可变对象的修改影响所有引用

对于**可变对象**（如列表、字典、集合），原地修改会改变对象本身，所有引用该对象的变量都会看到变化。这是引发共享状态问题的主要原因。

```python
config_a = {"level": 1, "mode": "auto"}
config_b = config_a

config_a["level"] = 5
print(config_b)  # {'level': 5, 'mode': 'auto'}，b 也被改了

config_b["mode"] = "manual"
print(config_a)  # {'level': 5, 'mode': 'manual'}，a 也被改了
```

只要通过任何一个引用修改了字典的内部内容，其他引用读到的就是修改后的状态。这种共享在有意为之的时候很方便，比如多个函数共用同一份配置；在无意为之的时候就会产生难以追踪的 bug，比如函数内部修改了传入的参数。所以在设计函数接口时，要明确是否允许修改传入对象，必要时先做拷贝。

## 4.7.5 浅拷贝

**浅拷贝**复制容器的顶层结构，生成一个新容器，但容器内嵌套的元素仍是共享引用。浅拷贝只复制了最外层，里层的对象还是原来那些。

```python
import copy

original = [[1, 2], [3, 4]]
shallow = copy.copy(original)

print(shallow is original)         # False，外层是新对象
print(shallow[0] is original[0])   # True，内层元素仍共享

shallow[0].append(99)
print(original)  # [[1, 2, 99], [3, 4]]，原列表的内层被改了
print(shallow)   # [[1, 2, 99], [3, 4]]
```

浅拷贝后，`shallow` 和 `original` 是两个不同的列表对象，但它们的第一个元素 `shallow[0]` 和 `original[0]` 仍指向同一个内层列表。修改这个内层列表，两边都会反映。如果只需要外层独立、内层共享可以接受，浅拷贝就足够了，性能也比深拷贝好。

## 4.7.6 浅拷贝方法

Python 提供多种浅拷贝方式，常见的有 `list.copy()`、`dict.copy()`、`copy.copy()`。前两个是类型自带的方法，第三个是 `copy` 模块的通用函数，适用于任意对象。这些方法在效果上等价，都是复制顶层结构、共享嵌套引用，选用哪一种主要看对象类型和代码风格。

```python
import copy

# 列表浅拷贝
lst = [1, 2, 3]
lst_copy1 = lst.copy()
lst_copy2 = copy.copy(lst)

# 字典浅拷贝
d = {"a": 1, "b": 2}
d_copy = d.copy()

# 通用浅拷贝
obj_copy = copy.copy(d)
```

## 4.7.7 切片实现浅拷贝

对列表进行**完整切片** `[:]` 会生成一个新列表，效果等同于浅拷贝。这是 Python 中很常见的写法，尤其在一些老代码里经常见到。

```python
original = [1, 2, 3, 4]
sliced = original[:]

print(sliced is original)  # False
print(sliced == original)  # True

sliced.append(5)
print(original)  # [1, 2, 3, 4]，外层独立
print(sliced)    # [1, 2, 3, 4, 5]
```

注意切片只复制顶层。如果列表里嵌套了可变对象，内层仍共享：

```python
nested = [[1, 2], [3, 4]]
nested_copy = nested[:]

nested_copy[0].append(99)
print(nested)  # [[1, 2, 99], [3, 4]]，内层共享
```

## 4.7.8 字典构造器实现浅拷贝

用 `dict()` 构造器传入一个已有字典，会生成一份浅拷贝。这种写法与 `d.copy()` 效果相同，选用哪一种看个人偏好。

```python
original = {"a": 1, "b": 2}
copied = dict(original)

print(copied is original)  # False
print(copied == original)  # True

copied["a"] = 100
print(original)  # {'a': 1, 'b': 2}，顶层键值独立
```

如果字典的值是可变对象，内层仍共享引用：

```python
original = {"info": [1, 2, 3]}
copied = dict(original)

copied["info"].append(4)
print(original)  # {'info': [1, 2, 3, 4]}，内层共享
```

## 4.7.9 集合构造器实现浅拷贝

`set()` 构造器传入一个集合，同样产生浅拷贝。由于集合元素必须可哈希，即不可变类型，所以集合的浅拷贝通常不会引发共享修改问题，但概念上仍是浅拷贝。

```python
original = {1, 2, 3}
copied = set(original)

print(copied is original)  # False
print(copied == original)  # True

copied.add(4)
print(original)  # {1, 2, 3}
print(copied)    # {1, 2, 3, 4}
```

如果集合里存的是元组这类不可变元素，浅拷贝后双方完全独立；如果存的是不可哈希对象的引用（不允许），则会出错。所以集合场景下浅拷贝的副作用风险较低。

## 4.7.10 深拷贝

**深拷贝**会递归地复制容器本身以及所有嵌套层级的元素，生成一个完全独立的新对象。深拷贝后的对象与原对象之间没有任何共享引用，修改一方完全不会影响另一方。

```python
import copy

original = [[1, 2], [3, 4]]
deep = copy.deepcopy(original)

print(deep is original)         # False
print(deep[0] is original[0])   # False，内层也是新对象

deep[0].append(99)
print(original)  # [[1, 2], [3, 4]]，原列表完全不受影响
print(deep)      # [[1, 2, 99], [3, 4]]
```

深拷贝会沿着对象结构一路复制下去，遇到列表、字典、集合等可变容器就重新创建一份，遇到不可变对象（如整数、字符串）则直接共享，因为不可变对象不需要复制。深拷贝的代价是性能开销较大，对于嵌套很深或体积很大的对象，调用前要权衡。

## 4.7.11 深拷贝方法

深拷贝的标准方法是 `copy.deepcopy()`，定义在 `copy` 模块中。它是唯一通用的深拷贝入口，适用于任意嵌套结构的对象。使用时只需 `import copy`，然后调用 `copy.deepcopy(obj)` 即可。

```python
import copy

data = {"users": [{"name": "Alice"}, {"name": "Bob"}]}
data_copy = copy.deepcopy(data)

data_copy["users"][0]["name"] = "Charlie"
print(data["users"][0]["name"])  # Alice，原数据未被修改
```

## 4.7.12 深拷贝的循环引用处理

深拷贝在内部维护一个**备忘录字典**（memo），记录已经拷贝过的对象。当遇到循环引用，即对象直接或间接地引用自身时，备忘录能让深拷贝识别出已访问的对象，直接复用已创建的副本，从而避免无限递归。例如一个列表 `a`，其内部某个元素又指回 `a` 本身，深拷贝依然能正确处理，得到结构等价的副本。这一机制对开发者完全透明，无需手动干预。

## 4.7.13 引用计数对组合对象的影响

Python 对每个对象维护一个**引用计数**，记录当前有多少引用指向它。组合对象（如列表、字典）会持有对其包含元素的引用，从而增加这些元素的引用计数。当某个元素的引用计数降为 0，意味着没有任何变量或容器再使用它，该元素就会被立即回收。理解这一点有助于解释为什么删除一个列表的元素不一定释放内存：只要还有其他引用指向该元素，它就仍然存活。引用计数机制对组合对象的销毁过程是递进的，外层容器先被释放，再依次释放内部元素。

## 4.7.14 垃圾回收对组合对象的影响

引用计数无法处理**循环引用**的情况，比如两个对象互相引用，即使外部已无引用，它们的引用计数都不为 0。Python 的垃圾回收器（garbage collector）专门负责检测并清理这种循环引用。对于组合对象，当多个容器相互嵌套引用形成环时，垃圾回收器会识别这些环并整体回收。这一过程对开发者透明，但在性能敏感的场景下，可以通过 `gc` 模块调整回收策略或手动触发回收。日常编程中无需关心，但理解其存在有助于排查内存占用异常的问题。

## 4.7.15 列表和字典的增量赋值 += 与 = 的不同影响

对于可变对象，`+=` 和 `=` 对引用的影响有本质区别。`+=` 是**原地操作**，调用对象的 `__iadd__` 方法，直接修改原对象，所有引用都会看到变化。`=` 是**重新绑定**，让变量指向一个新对象，不影响原对象和其他引用。

```python
# 列表的 += 是原地修改
a = [1, 2, 3]
b = a
a += [4, 5]
print(a)  # [1, 2, 3, 4, 5]
print(b)  # [1, 2, 3, 4, 5]，b 也变了，因为是原地修改

# 列表的 = 是重新绑定
a = [1, 2, 3]
b = a
a = a + [4, 5]
print(a)  # [1, 2, 3, 4, 5]
print(b)  # [1, 2, 3]，b 不变，因为 a 指向了新对象
```

`a += [4, 5]` 等价于 `a.extend([4, 5])`，在原列表上追加元素，`b` 与 `a` 引用同一对象，自然同步变化。`a = a + [4, 5]` 中 `a + [4, 5]` 创建了一个新列表，然后 `a` 重新绑定到这个新列表，`b` 仍指向原来的列表，所以不变。

字典的 `|=`（Python 3.9+）与 `=` 也有类似的区别。`d |= other` 是原地更新，`d = d | other` 是创建新字典后重新绑定。函数内部修改传入的可变参数时，这一区别尤其重要：用 `+=` 会改变外部传入的对象，用 `=` 不会。

```python
def add_item(lst):
    lst += [99]  # 原地修改，影响外部

data = [1, 2]
add_item(data)
print(data)  # [1, 2, 99]

def rebind(lst):
    lst = lst + [99]  # 重新绑定，不影响外部

data = [1, 2]
rebind(data)
print(data)  # [1, 2]
```

理解这一差异，能避免函数副作用相关的常见 bug。

::: note 拷贝策略的选择
绝大多数场景下浅拷贝已经够用，性能也更好。只有当容器嵌套了可变对象，且需要双方完全独立时，才使用深拷贝。函数内部若要修改传入的可变参数而不影响调用方，应在函数入口处先做拷贝。
:::

## 练习题

### 第 1 题：写出下列引用操作的输出结果

阅读下面这段代码，在不运行的情况下写出它的输出。

```python
a = [1, 2, 3]
b = a
b.append(4)
print(a)
print(a is b)

c = a.copy()
c.append(5)
print(a)
print(a is c)
```

::: details 参考答案
输出如下：

```
[1, 2, 3, 4]
True
[1, 2, 3, 4]
False
```

`b = a` 是赋值而非拷贝，`b` 和 `a` 引用同一个列表对象，所以 `b.append(4)` 后 `a` 也变了，`a is b` 为 `True`。`a.copy()` 是浅拷贝，生成一个新列表，`c` 与 `a` 是两个不同对象，`a is c` 为 `False`，所以 `c.append(5)` 不影响 `a`。理解赋值与拷贝的区别是避开引用陷阱的第一步。
:::

### 第 2 题：用深拷贝避免嵌套列表的共享修改

给定嵌套列表 `original = [[1, 2], [3, 4]]`，请分别用浅拷贝和深拷贝创建两份副本，然后在内层列表上追加元素，观察原列表受到的影响，并打印三份列表的最终状态。

::: details 参考答案
```python
import copy

original = [[1, 2], [3, 4]]

shallow = copy.copy(original)
deep = copy.deepcopy(original)

shallow[0].append(99)
deep[1].append(88)

print("original:", original)
print("shallow: ", shallow)
print("deep:    ", deep)
```

输出：

```
original: [[1, 2, 99], [3, 4]]
shallow:  [[1, 2, 99], [3, 4]]
deep:     [[1, 2, 99], [3, 4, 88]]
```

浅拷贝只复制外层列表，内层列表仍是共享引用，所以 `shallow[0].append(99)` 同时改变了 `original` 的第一个内层列表。深拷贝递归复制所有层级，`deep[1].append(88)` 只影响 `deep` 自身，`original` 和 `shallow` 都不受影响。嵌套可变对象需要完全独立时必须用深拷贝。
:::

### 第 3 题：分析 += 与 = 对引用的不同影响

下面两个函数看似都在向列表追加元素，但行为不同。请阅读代码，预测两次调用的输出，并解释差异原因。

```python
def modify_inplace(lst):
    lst += [99]

def rebind_local(lst):
    lst = lst + [99]

data1 = [1, 2]
modify_inplace(data1)
print("data1:", data1)

data2 = [1, 2]
rebind_local(data2)
print("data2:", data2)
```

::: details 参考答案
输出如下：

```
data1: [1, 2, 99]
data2: [1, 2]
```

`modify_inplace` 中 `lst += [99]` 是原地操作，调用列表的 `__iadd__` 方法，等价于 `lst.extend([99])`，直接修改传入的对象，所以外部的 `data1` 也变了。`rebind_local` 中 `lst = lst + [99]` 先创建一个新列表，然后把局部变量 `lst` 重新绑定到这个新列表，外部的 `data2` 仍指向原列表，不受影响。函数内部修改可变参数时，`+=` 会产生副作用波及调用方，`=` 不会。需要避免副作用时应在入口处拷贝，或用 `=` 重新绑定。
:::

### 第 4 题：项目练习题（命令行任务管理器）

命令行任务管理器需要实现一个 `duplicate_tasks(tasks)` 函数，返回任务列表的一份完整副本，后续对副本的修改不能影响原列表。每个任务是包含 `name` 和 `subtasks` 的字典，`subtasks` 是子任务名列表。请用合适的拷贝方式实现，并验证修改副本不会影响原列表。

::: details 参考答案
```python
import copy

def duplicate_tasks(tasks):
    return copy.deepcopy(tasks)


tasks = [
    {"name": "写文档", "subtasks": ["大纲", "初稿", "修订"]},
    {"name": "测试", "subtasks": ["单元测试", "集成测试"]},
]

backup = duplicate_tasks(tasks)

backup[0]["subtasks"].append("终审")
backup[1]["name"] = "集成测试"

print("原列表:", tasks)
print("副本:  ", backup)
```

输出：

```
原列表: [{'name': '写文档', 'subtasks': ['大纲', '初稿', '修订']}, {'name': '测试', 'subtasks': ['单元测试', '集成测试']}]
副本:   [{'name': '写文档', 'subtasks': ['大纲', '初稿', '修订', '终审']}, {'name': '集成测试', 'subtasks': ['单元测试', '集成测试']}]
```

任务结构嵌套了可变对象（`subtasks` 列表），必须用深拷贝才能保证副本与原列表完全独立。浅拷贝会让副本的 `subtasks` 与原列表共享同一个内层列表，修改一处会影响另一处。任务管理器在撤销、历史记录、批量操作等场景经常需要复制任务数据，深拷贝是避免共享状态污染的可靠手段。
:::

## 常见错误

**错误 1 · 浅拷贝后修改嵌套列表，原列表跟着变**

原因:`copy.copy()`、`list.copy()`、`list[:]` 等浅拷贝方式只复制外层容器，内层可变对象仍是共享引用。通过副本修改内层嵌套列表，原对象对应位置同步变化。

解决:需要完全独立时用 `copy.deepcopy()` 递归复制整个对象树。列表只含数字、字符串等不可变元素时浅拷贝即可，无需深拷贝。

**错误 2 · 用 `is` 比较内容，`a is b` 返回 `False` 但内容相同**

原因:`is` 比较对象的身份（内存地址），`==` 比较内容。两个独立创建的列表即使内容完全相同，也是不同的对象，`is` 返回 `False`。把 `is` 当作 `==` 使用会导致内容相同的对象被误判为不相等。

解决:判断内容是否相等用 `==`。`is` 仅用于判断 `None`、`True`、`False` 或确认两个变量是否引用同一对象。

**错误 3 · 函数内 `lst += items` 修改了调用方的列表**

原因:列表的 `+=` 调用 `__iadd__` 方法，就地修改原对象，等价于 `extend`。函数内部对传入的列表参数使用 `+=`，会改变调用方传进来的列表，产生预期外的副作用。

解决:不想修改原列表时用 `lst = lst + items` 创建新列表，或在函数入口处先拷贝 `lst = lst.copy()`。不可变类型（元组、字符串）的 `+=` 会回退到创建新对象，不存在此问题。

**错误 4 · 对大型嵌套结构滥用深拷贝导致性能下降**

原因:`copy.deepcopy()` 递归遍历整个对象树，对每个可变对象都重新创建，遇到循环引用还要维护备忘录字典。对体积大或嵌套深的对象，深拷贝的开销显著，在循环或高频调用场景下会拖慢程序。

解决:只在容器嵌套了可变对象且需要完全独立时才用深拷贝。只含不可变元素的容器用浅拷贝即可。能通过重新构造对象（如推导式）实现独立副本时，优先用构造方式替代深拷贝。
