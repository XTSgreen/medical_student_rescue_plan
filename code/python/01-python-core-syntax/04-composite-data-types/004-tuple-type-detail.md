# 4.4 元组类型（Tuple）专题


元组是 Python 中另一种有序序列类型，外形与列表相似，但创建后不可修改。列表像可以随时调整的清单，元组则像已经封存的归档记录，一旦确立就无法再改动。本专题将逐一拆解元组的字面量定义、不可变性、索引切片、方法、打包与拆包、作为字典键与集合元素的要求，以及与列表的相互转换和不可变性的细节边界，帮助你理解何时该用元组代替列表。

## 4.4.1 元组字面量定义

元组字面量用圆括号 `()` 包裹，元素之间以逗号分隔。Python 允许省略圆括号，直接用逗号分隔的多个值就构成一个元组，这种写法在函数返回多值时特别常见。省略圆括号的元组叫做隐式元组，解释器根据逗号判断这是一个元组而非普通表达式。

```python
t1 = (1, 2, 3)
print(t1)                 # (1, 2, 3)
print(type(t1))           # <class 'tuple'>

t2 = 1, 2, 3              # 圆括号可省略
print(t2)                 # (1, 2, 3)
print(t1 == t2)           # True

# 函数返回多值就是返回一个元组
def min_max(nums):
    return min(nums), max(nums)

result = min_max([3, 1, 4, 1, 5])
print(result)             # (1, 5)
print(type(result))       # <class 'tuple'>
```

隐式元组让多值返回的写法非常自然，调用方用拆包接收即可。圆括号在元素较多或需要明确分组时仍然推荐使用，以提高可读性。元组字面量在解释器读取时直接构造出元组对象，无需调用构造函数。

## 4.4.2 单元素元组定义必须加逗号

单元素元组必须写成 `(value,)`，结尾的逗号不可省略。`(value)` 只是带括号的表达式，Python 会把它当成普通值而非元组。这一规则源于括号在 Python 中有多重含义：表达式分组、函数调用、元组字面量，单元素时只有逗号才能消除歧义。

```python
single = (42,)
print(type(single))       # <class 'tuple'>
print(single)             # (42,)

not_tuple = (42)
print(type(not_tuple))    # <class 'int'>

# 即使没有括号，加逗号也是元组
also_tuple = 42,
print(type(also_tuple))   # <class 'tuple'>
```

::: note 末尾逗号的习惯
多元素元组的末尾逗号可有可无，`(1, 2, 3,)` 与 `(1, 2, 3)` 完全等价。许多项目约定多元素元组也保留末尾逗号，便于后续追加元素时少改一行，也避免版本控制产生多余的 diff 噪音。这一习惯在列表和字典字面量中同样适用。
:::

单元素元组的逗号规则是元组最容易踩坑的地方。在函数调用时误写 `func((x))` 实际传的是 x 而非元组，要传单元素元组应写成 `func((x,))`。

## 4.4.3 空元组定义

空元组写成 `()` 或调用 `tuple()`，两者等价。空元组用处相对较少，主要出现在需要返回无值的函数中，或作为占位符。注意空元组不需要逗号，这是单元素元组规则的一个例外，因为空元组的括号本身就是元组标识，没有歧义。

```python
empty1 = ()
empty2 = tuple()
print(len(empty1))        # 0
print(empty1 == empty2)   # True
print(type(empty1))       # <class 'tuple'>
```

`tuple()` 构造函数还可以把其他可迭代对象转换为元组，例如 `tuple([1, 2, 3])` 得到 `(1, 2, 3)`，`tuple("abc")` 得到 `('a', 'b', 'c')`，`tuple(range(5))` 得到 `(0, 1, 2, 3, 4)`。转换产生新元组对象，原可迭代对象不受影响。

## 4.4.4 元组的不可变性

元组的核心特征是**不可变**。一旦创建，元组的长度和每个位置的元素引用就固定下来，无法通过索引赋值修改，也无法 append、remove 或 sort。尝试修改元组元素会抛出 `TypeError`。

```python
point = (3, 5)
# point[0] = 4            # TypeError: 'tuple' object does not support item assignment

# 元组没有任何修改类方法
# point.append(6)         # AttributeError
# point.remove(3)         # AttributeError
```

不可变性带来几个实际优势。元组可以作为字典的键和集合的元素，列表不行，因为字典和集合要求键可哈希，而可变对象不可哈希。元组在多线程环境下天然安全，无需加锁，因为没有代码能修改它。元组还向函数调用方传递一个明确信号：这个值不会被改动，可以放心传递。实际开发中，元组适合表示一旦确定就不应改动的数据，例如坐标点、RGB 颜色值、数据库记录的主键组合等。

## 4.4.5 元组的索引与切片

元组的索引和切片语法与列表完全一致，只是返回的新序列也是元组而非列表。索引从 0 开始，支持负向索引从 -1 倒数。切片用 `[start:stop:step]` 语法，遵循左闭右开原则，返回新元组，原元组不变。

```python
record = ("U001", "active", 45, "admin")
print(record[0])          # U001
print(record[-1])         # admin
print(record[1:3])        # ('active', 45)，切片仍是元组
print(record[::-1])       # ('admin', 45, 'active', 'U001')，反转

# 索引越界抛异常
# record[4]               # IndexError
# 切片越界自动截断，不报错
print(record[1:100])      # ('active', 45, 'admin')
```

掌握列表的索引切片就掌握了元组的索引切片，唯一的差异是切片结果类型仍是元组。索引越界抛 `IndexError`，切片越界自动截断到有效范围，这些行为与列表一致。

## 4.4.6 元组拼接和重复

`+` 运算符把两个元组拼接成一个新元组，`*` 运算符把元组重复若干次生成新元组。由于元组不可变，这些操作都不会修改原元组，而是返回新对象。`+` 两边必须都是元组，元组与列表拼接会抛 `TypeError`。

```python
base = (1, 2, 3)
extra = (4, 5)
combined = base + extra
print(combined)           # (1, 2, 3, 4, 5)
print(base)               # (1, 2, 3)，原元组不变

repeated = (0,) * 4
print(repeated)           # (0, 0, 0, 0)

pattern = (1, 2) * 3
print(pattern)            # (1, 2, 1, 2, 1, 2)
```

注意单元素元组 `(0,)` 必须加逗号，否则 `(0)` 只是个整数，整数乘以 4 得到的是 0 而非元组。拼接和重复都是 O(n) 操作，需要拷贝所有元素到新元组。频繁拼接元组时性能不如列表的 `extend`，因为元组每次拼接都生成新对象，而列表可以就地扩展。

## 4.4.7 元组方法：仅 count() 和 index()

元组只有两个公开方法：`count(value)` 统计某值出现的次数，`index(value, start, end)` 返回第一个匹配元素的位置。列表的 append、remove、sort 等修改类方法在元组上都不存在，这反映了元组作为只读容器的设计取向。

```python
t = (1, 2, 2, 3, 2, 4)
print(t.count(2))         # 3
print(t.count(5))         # 0，不存在返回 0
print(t.index(2))         # 1，第一个 2 的位置
print(t.index(2, 2))      # 2，从索引 2 开始找

# index 找不到抛异常
# t.index(5)              # ValueError: tuple.index(x): x not in tuple
```

`index` 找不到目标值时会抛 `ValueError`，调用前最好先用 `in` 检查或用 try/except 捕获。`count` 找不到时返回 0，不会抛异常。两个方法都是线性扫描，时间复杂度 O(n)。方法数量少意味着元组的接口简洁，专注于读取而非修改。

## 4.4.8 元组打包

元组打包是把多个值组合成一个元组的过程。在 Python 中，用逗号分隔的多个值会自动打包成元组，无需显式构造。这种机制让多值赋值和函数多值返回变得自然流畅。

```python
# 多个值打包成一个元组
point = 3, 5, 8
print(point)              # (3, 5, 8)
print(type(point))        # <class 'tuple'>

# 函数返回多个值就是返回一个打包的元组
def get_user_info():
    name = "alice"
    age = 30
    role = "admin"
    return name, age, role    # 打包成元组返回

info = get_user_info()
print(info)               # ('alice', 30, 'admin')
print(type(info))         # <class 'tuple'>
```

打包操作是隐式的，由逗号触发。圆括号只是可选的分组符号，不影响打包行为。理解打包机制有助于理解函数多值返回的本质：Python 函数只能返回一个值，多值返回是返回一个打包好的元组。

## 4.4.9 元组拆包

元组拆包是把元组的各个元素一次性赋给多个变量，语法直观，是 Python 中处理多值的核心技巧。变量数必须与元组长度一致，否则抛 `ValueError`。拆包与打包互为逆操作，两者配合让多值传递非常简洁。

```python
# 基本拆包
point = (3, 5)
x, y = point
print(x, y)               # 3 5

# 隐式元组的拆包
a, b, c = 1, 2, 3         # 右侧先打包成 (1, 2, 3) 再拆包
print(a, b, c)            # 1 2 3

# 变量数不匹配会报错
# t = (1, 2, 3)
# x, y = t                # ValueError: too many values to unpack
```

拆包让函数返回值的接收变得清晰。`name, age, role = get_user_info()` 直接把元组的三个元素分别赋给三个变量，可读性远胜用索引逐个取值。拆包也适用于列表和任何可迭代对象，只要变量数与元素数一致。

## 4.4.10 元组拆包使用星号收集剩余元素

拆包时在一个变量前加星号 `*`，该变量会收集剩余的所有元素，组装成一个列表。这种用法在处理前几个元素明确、剩余可变的场景时很方便。带星号的变量只能出现一个，否则解释器无法确定如何分配。

```python
record = (1, 2, 3, 4, 5)
first, *rest = record
print(first)              # 1
print(rest)               # [2, 3, 4, 5]
print(type(rest))         # <class 'list'>

*init, last = record
print(init)               # [1, 2, 3, 4]
print(last)               # 5

first, *middle, last = record
print(first)              # 1
print(middle)             # [2, 3, 4]
print(last)               # 5
```

::: note 星号收集的结果是列表
无论被拆包的是元组还是列表，星号变量收集的结果始终是列表类型。如果剩余元素为零个，星号变量得到空列表 `[]`，不会报错。这一行为在处理变长输入时非常实用。
:::

星号收集常用于忽略中间元素，例如 `first, *_ = record` 只取第一个元素，其余用 `_` 丢弃。这种写法比先取索引更清晰地表达了只关心首元素的意图。

## 4.4.11 元组拆包可嵌套

拆包支持嵌套结构，当元组的元素本身也是元组或序列时，可以用对应的嵌套变量形式一次性解开所有层级。嵌套拆包的变量结构需要与元组的结构完全匹配，否则抛出 `ValueError`。

```python
# 嵌套元组的拆包
data = (1, (2, 3))
a, (b, c) = data
print(a, b, c)            # 1 2 3

# 更深的嵌套
nested = (1, (2, (3, 4)))
a, (b, (c, d)) = nested
print(a, b, c, d)         # 1 2 3 4

# 结构不匹配会报错
# data = (1, (2, 3))
# a, b, c = data          # ValueError
```

嵌套拆包在处理结构化数据时很有用。例如一个表示用户信息的元组 `("alice", (30, "admin"))`，可以用 `name, (age, role) = user` 一次性取出所有字段，比逐层索引访问更直观。结合星号收集，嵌套拆包能应对相当复杂的数据结构。

## 4.4.12 元组拆包用于 for 循环

for 循环遍历元素为元组的可迭代对象时，可以直接在循环变量处使用拆包语法，每次迭代把当前元组的元素分别赋给对应变量。这是 Python 中遍历键值对、坐标对等成组数据的惯用写法。

```python
# 遍历坐标列表
points = [(1, 2), (3, 4), (5, 6)]
for x, y in points:
    print(f"x={x}, y={y}")
# x=1, y=2
# x=3, y=4
# x=5, y=6

# 遍历字典项
scores = {"alice": 90, "bob": 85, "carol": 92}
for name, score in scores.items():
    print(f"{name}: {score}")
# alice: 90
# bob: 85
# carol: 92

# 配合 enumerate 拆包
for index, value in enumerate(["a", "b", "c"]):
    print(f"{index}: {value}")
# 0: a
# 1: b
# 2: c
```

循环中拆包让代码无需通过索引访问元组内部，可读性显著提升。`dict.items()` 返回的每个元素是 `(key, value)` 元组，用 `for k, v in d.items()` 直接拆开是遍历字典的标准写法。

## 4.4.13 元组作为字典键的要求

字典的键必须是可哈希对象，元组在元素全部可哈希时可以作为字典的键。可哈希意味着对象在其生命周期内哈希值不变，且可以与其他对象比较相等。不可变类型如数字、字符串、元组都是可哈希的，可变类型如列表、字典、集合不可哈希。

```python
# 元组作为字典键：元素全部不可变
locations = {
    (39.9, 116.4): "Beijing",
    (31.2, 121.5): "Shanghai",
    (23.1, 113.3): "Guangzhou",
}
print(locations[(39.9, 116.4)])   # Beijing

# 元组作为键查找
point = (31.2, 121.5)
print(locations.get(point))       # Shanghai
```

当元组的元素中包含可变对象时，该元组不可哈希，不能作为字典键。这是因为元组的哈希值依赖于其元素的哈希值，如果元素是可变的，哈希值就无法保持稳定。

```python
# 含列表的元组不可哈希
# bad_key = (1, [2, 3])
# d = {bad_key: "value"}    # TypeError: unhashable type: 'list'

# 含元组的元组可以哈希（嵌套元组元素也都不可变）
good_key = (1, (2, 3))
d = {good_key: "value"}
print(d[(1, (2, 3))])      # value
```

用元组作为字典键的常见场景包括坐标到值的映射、多字段联合主键查询等。相比把多个字段拼成字符串作为键，元组保留了类型信息，比较时也更高效。

## 4.4.14 元组作为集合元素的要求

集合与字典类似，其元素也必须是可哈希对象。元组在元素全部可哈希时可以作为集合的元素，可以用于去重和集合运算。含可变对象的元组不可哈希，不能加入集合。

```python
# 元组作为集合元素
points = {(1, 2), (3, 4), (1, 2), (5, 6)}
print(points)             # {(1, 2), (3, 4), (5, 6)}，自动去重

# 用集合对坐标列表去重
coords = [(1, 2), (3, 4), (1, 2), (5, 6), (3, 4)]
unique = list(set(coords))
print(len(unique))        # 3

# 含列表的元组不能加入集合
# bad = {(1, [2, 3])}     # TypeError: unhashable type: 'list'
```

集合的成员检查是 O(1)，远快于列表的 O(n) 线性扫描。当需要频繁判断某个元组是否在一组元组中时，用集合存储比用列表高效得多。元组在集合中的去重特性也常用于去除重复的复合记录。

## 4.4.15 元组与列表的相互转换

`tuple()` 把列表转换为元组，`list()` 把元组转换为列表。转换产生新对象，原对象不变。这种转换在需要可变与不可变特性切换时常用，例如先在列表上修改，修改完成后再转为元组保护数据。

```python
# 列表转元组
lst = [1, 2, 3]
t = tuple(lst)
print(t)                  # (1, 2, 3)
print(type(t))            # <class 'tuple'>

# 元组转列表
t = (1, 2, 3)
lst = list(t)
lst.append(4)
print(lst)                # [1, 2, 3, 4]
print(t)                  # (1, 2, 3)，原元组不变

# 元组转列表修改后再转回
config = ("localhost", 8080, False)
temp = list(config)
temp[1] = 9090
config = tuple(temp)
print(config)             # ('localhost', 9090, False)
```

转换是 O(n) 操作，需要遍历整个序列复制所有元素。频繁在元组与列表之间互转通常意味着数据结构选择不当，应当一开始就根据是否需要修改来选定类型。需要修改时用列表，需要保护时用元组，明确意图比反复转换更可靠。

## 4.4.16 元组不可变性的边界

元组的不可变是指元组本身的结构和元素引用不可变，长度固定、每个位置指向的对象不可更换。但如果元素本身是可变对象，那个对象的内部状态仍然可以修改。这一点经常让初学者困惑，需要仔细区分元组的不可变与元素对象的不可变。

```python
t = (1, [2, 3], "hello")

# 不能修改元组本身的结构
# t[0] = 10               # TypeError

# 但可以修改可变元素的内容
t[1].append(4)
t[1].extend([5, 6])
print(t)                  # (1, [2, 3, 4, 5, 6], 'hello')

# 字符串是不可变的，无法修改
# t[2][0] = "H"           # TypeError: 'str' object does not support item assignment
```

`t[1]` 始终指向同一个列表对象，元组的不可变性没有被破坏，因为元组记录的是引用而非内容。但这个列表对象本身是可变的，可以 append、remove、sort。这类似一个固定名单，名单上每个位置对应的人不变，但人自身的状态可以改变。

::: note 含可变元素的元组不可哈希
元组的哈希值依赖其元素的哈希值。当元组包含可变对象时，可变对象的哈希值可能随内容改变而变化，导致整个元组的哈希值不稳定。因此含可变元素的元组不可哈希，不能作为字典键或集合元素。只有当元组的所有元素都是不可变类型时，元组才可哈希。
:::

```python
# 全不可变元素：可哈希
t1 = (1, 2, "a")
print(hash(t1))           # 返回一个整数

# 含可变元素：不可哈希
t2 = (1, [2, 3])
# hash(t2)                # TypeError: unhashable type: 'list'

# 修改可变元素前后元组身份不变，但内容已变
print(id(t2))             # 某个内存地址
t2[1].append(4)
print(id(t2))             # 同一个地址，元组对象本身没变
print(t2)                 # (1, [2, 3, 4])，但内容已经改变
```

理解元组不可变性的边界非常重要。不可变保证的是元组结构的稳定，而非其中可变元素内容的冻结。如果需要一个真正完全不可变的数据结构，应该确保元组中只存放不可变类型的元素，或者使用命名元组、dataclass 等更高级的数据建模工具。

掌握元组之后，你已经理解了 Python 中两种基本的序列类型。列表负责可变场景，元组负责不可变场景，两者各司其职。下一节将进入字典与集合等基于哈希的容器类型，进一步扩展处理实际数据的能力。

## 练习题

### 第 1 题：写出下列元组操作的输出结果

阅读下面这段代码，在不运行的情况下写出它的输出。

```python
t = (10, 20, 30, 20, 40)
print(t[1])
print(t[-1])
print(t.count(20))
print(t.index(20))
print(len(t))
```

::: details 参考答案
输出如下。`t[1]` 取第二个元素，`t[-1]` 取最后一个，`count(20)` 统计 20 出现两次，`index(20)` 返回第一个 20 的位置，`len(t)` 返回元素个数。

```
20
40
2
1
5
```

元组的索引、计数、查找方法与列表完全一致，区别只在于元组不可变，没有 `append`、`remove`、`sort` 等修改类方法。
:::

### 第 2 题：用元组拆包交换两个变量的值

请用元组拆包的语法交换变量 `a` 和 `b` 的值，不借助第三个临时变量。初始值 `a = 10`，`b = 20`。

::: details 参考答案
```python
a = 10
b = 20

a, b = b, a

print("a =", a)
print("b =", b)
```

输出：

```
a = 20
b = 10
```

右侧 `b, a` 先打包成元组 `(20, 10)`，再拆包赋值给左侧的 `a` 和 `b`。这种写法利用了 Python 的隐式元组打包与拆包机制，是交换变量值的最简洁方式。
:::

### 第 3 题：用元组作为字典键存储坐标信息

请用一个字典存储几个城市的经纬度坐标，键是 `(纬度, 经度)` 形式的元组，值是城市名。然后根据一个坐标查询对应的城市。

::: details 参考答案
```python
cities = {
    (39.9, 116.4): "北京",
    (31.2, 121.5): "上海",
    (23.1, 113.3): "广州",
}

query = (31.2, 121.5)
print(cities.get(query))
```

输出 `上海`。元组是不可变类型，可哈希，能作为字典键。用元组作为复合键比把多个字段拼成字符串更清晰，比较时也更高效。这种写法在地理信息、配置查询等场景很常见。
:::

### 第 4 题：项目练习题（命令行任务管理器）

命令行任务管理器中每个任务有 `name`、`status`、`priority` 三个字段。一旦任务创建，它的名称和优先级就不应再改变。请用一个字典列表存储任务，但把不可变字段用元组表示，演示如何安全地读取这些字段。

::: details 参考答案
```python
tasks = [
    {"id": ("T001", 2), "status": "todo", "name": "写文档"},
    {"id": ("T002", 1), "status": "todo", "name": "修复 Bug"},
    {"id": ("T003", 3), "status": "done", "name": "评审代码"},
]

# 读取不可变字段
for task in tasks:
    task_id, priority = task["id"]
    print(f"{task_id} [优先级 {priority}] {task['name']} - {task['status']}")

# status 可以修改
tasks[0]["status"] = "done"
```

输出：

```
T001 [优先级 2] 写文档 - todo
T002 [优先级 1] 修复 Bug - todo
T003 [优先级 3] 评审代码 - done
```

把任务编号和优先级打包成元组存入 `id` 字段，元组的不可变性保证了这两个字段不会被意外修改，而 `status` 用普通字符串存储，可以随业务流程更新。拆包语法让读取元组字段很自然。
:::

## 常见错误

**错误 1 · `(42)` 不是元组，`type((42))` 返回 `<class 'int'>`**

原因:圆括号在 Python 中兼作表达式分组符号，`(42)` 被解释为带括号的整数 42，而非单元素元组。只有逗号才是元组的标识。

解决:单元素元组必须写成 `(42,)`，末尾逗号不可省略。无需括号时直接写 `42,` 也可构成元组。

**错误 2 · `TypeError: unhashable type: 'list'`（元组含可变元素）**

原因:元组本身不可变，但当其元素包含列表等可变对象时，元组的哈希值依赖内部元素的哈希值，可变元素的存在导致整个元组不可哈希，无法作为字典键或集合元素。

解决:把元组内的可变元素替换为不可变类型，例如把内层列表改成元组 `(1, (2, 3))`。需要存储可变数据时不要用元组作为键，改用字符串或整数等可哈希类型。

**错误 3 · 元组内嵌套列表被修改，元组内容随之改变**

原因:元组的不可变仅指结构和元素引用固定，不约束元素对象自身的内部状态。当元素是可变对象（如列表）时，通过该引用修改对象内容，元组看上去就变了。

解决:需要完全不可变的数据时，确保元组中只存放不可变类型的元素。如果必须包含可变对象，在文档或注释中明确标注哪些位置可变，避免调用方误判数据的稳定性。
