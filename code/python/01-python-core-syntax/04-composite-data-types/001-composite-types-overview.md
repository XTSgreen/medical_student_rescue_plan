# 4.1 组合数据类型分类与通用特性


3.9 节用嵌套控制结构把分支、循环、异常处理组合成完整程序，控制流程解决的是"怎么做"的问题。但程序要处理的数据该装在什么容器里、为什么有的容器能改有的不能改、有的能查重有的不能查重，这些"用什么装"的问题需要回到数据类型本身回答。第 2 章介绍过列表、元组、字典、集合的基本用法，本章做进阶梳理。本节从分类体系出发，统一讲解可变性、可哈希性以及长度、成员检查、迭代、比较等所有组合类型共享的属性与操作。

## 4.1.1 组合数据类型分类

Python 的组合数据类型按组织方式分为三大类：**序列类型**（Sequence）、**映射类型**（Mapping）和**集合类型**（Set）。序列类型按位置顺序存放元素，每个元素有固定编号，通过索引访问。映射类型以键值对形式组织数据，通过键而非位置来查找对应的值。集合类型存储一组不重复的元素，没有顺序也没有键，侧重于成员关系判断和集合运算。这三大类覆盖了 Python 所有内置组合类型，构成了数据组织的完整框架。

```python
# 三大类组合数据类型示例
seq = [10, 20, 30]              # 序列类型：列表
mapping = {"a": 1, "b": 2}     # 映射类型：字典
collection = {10, 20, 30}      # 集合类型：集合

print(type(seq))       # <class 'list'>
print(type(mapping))   # <class 'dict'>
print(type(collection))# <class 'set'>
```

三类类型各自适合不同的场景。需要按顺序存取一批数据时用序列类型，需要通过名字查找数据时用映射类型，需要去重或做交并差运算时用集合类型。后续章节会逐一展开每类的具体用法，本节先建立整体认识。

## 4.1.2 序列类型包含

序列类型是一个大类，Python 内置的序列类型有四种：**列表**（list）、**元组**（tuple）、**字符串**（str）和**范围**（range）。它们都支持按位置索引、切片和迭代，但在可变性和元素类型上有差异。列表和元组可以存放任意类型元素，字符串的元素是单个字符，range 的元素是按步长生成的整数。这四种类型的详细操作会在后续章节分别讲解，这里仅作分类对照，帮助你建立序列类型的完整清单。

```python
# 四种序列类型一览
list_example = [1, 2, 3]
tuple_example = (1, 2, 3)
str_example = "abc"
range_example = range(3)

# 它们都支持索引访问
print(list_example[0])     # 1
print(tuple_example[0])    # 1
print(str_example[0])      # a
print(range_example[0])    # 0
```

## 4.1.3 可变数据类型

可变数据类型指的是对象创建之后，可以在原对象上直接修改内容，而不必新建对象。Python 中**列表**、**字典**和**集合**是可变类型。对列表可以追加、删除、替换元素，对字典可以增删改键值对，对集合可以添加或丢弃元素，这些操作都作用于对象本身，对象的身份（内存地址）保持不变。

```python
# 可变类型：原地修改，身份不变
data = [1, 2, 3]
print(id(data))          # 查看初始地址
data.append(4)           # 原地追加
data[0] = 99             # 原地替换
print(data)              # [99, 2, 3, 4]
print(id(data))          # 地址不变

config = {"level": 1}
print(id(config))
config["level"] = 2      # 原地修改值
config["status"] = "ok"  # 原地新增键
print(config)            # {'level': 2, 'status': 'ok'}
print(id(config))        # 地址不变
```

可变性带来的好处是操作高效，追加和修改不需要复制整个对象。代价是多个变量可能引用同一个可变对象，通过一处修改会影响到其他引用方，这一点在函数传参和嵌套结构中需要特别留意。

## 4.1.4 不可变数据类型

不可变数据类型指的是对象创建之后，其内容无法在原对象上被修改。Python 中**元组**、**字符串**、**范围**（range）和**冻结集合**（frozenset）是不可变类型。任何看起来像修改的操作，实际都是创建了一个新对象。例如字符串的拼接、元组的切片，返回的都是新对象，原对象保持不变。

```python
# 不可变类型：修改产生新对象，身份改变
text = "hello"
print(id(text))
text = text + " world"    # 拼接生成新字符串
print(text)              # hello world
print(id(text))          # 地址改变

point = (1, 2)
# point[0] = 10          # TypeError: 'tuple' object does not support item assignment
new_point = point + (3,)  # 生成新元组
print(point)             # (1, 2)，原元组不变
print(new_point)         # (1, 2, 3)
```

不可变性保证了对象内容的稳定，这在作为字典键、集合元素或多线程共享数据时非常重要。不可变对象一旦创建就不用担心被意外篡改，代码行为更可预测。

## 4.1.5 可哈希类型

可哈希类型是指对象在其生命周期内拥有固定不变的哈希值，可以用作字典的键或集合的元素。Python 中所有**不可变类型**都是可哈希的，包括数字、字符串、元组、frozenset 等。字典和集合内部依靠哈希表来快速定位元素，可哈希是它们对键和元素的基本要求。

```python
# 可哈希类型作为字典键
scores = {
    "alice": 90,        # 字符串键
    1001: 85,           # 整数键
    (0, 0): "origin"    # 元组键
}
print(scores["alice"])       # 90
print(scores[(0, 0)])        # origin

# 可哈希类型作为集合元素
points = {(0, 0), (1, 1), (2, 2)}
print((1, 1) in points)      # True
```

需要特别注意的是，元组本身是不可变类型，但如果元组内部包含可变元素（如列表），这个元组就不可哈希。因为可变元素的内容变化会导致元组的哈希值失效，Python 会直接禁止这种元组用作键。

```python
# 元组含可变元素时不可哈希
try:
    bad_key = {[1, 2]: "value"}
except TypeError as e:
    print(e)  # unhashable type: 'list'

try:
    bad_tuple_key = {([1, 2], 3): "value"}
except TypeError as e:
    print(e)  # unhashable type: 'list'
```

## 4.1.6 不可哈希类型

不可哈希类型就是可变类型，包括**列表**、**字典**和**集合**。这些对象的内容可以随时改变，哈希值无法保持固定，因此不能用作字典的键或集合的元素。强行使用会抛出 TypeError。

```python
# 不可哈希类型不能作为键或集合元素
try:
    d = {[1, 2]: "list as key"}
except TypeError as e:
    print(e)  # unhashable type: 'list'

try:
    s = {{1, 2}, {3, 4}}
except TypeError as e:
    print(e)  # unhashable type: 'set'

# 如果需要把集合作为键，改用 frozenset
fs = frozenset({1, 2})
d = {fs: "frozenset as key"}
print(d[fs])  # frozenset as key
```

frozenset 是集合的不可变版本，可哈希，弥补了集合无法作为键的不足。理解可哈希与不可哈希的边界，能帮助你在设计数据结构时正确选择键的类型。

## 4.1.7 容器类型与原子类型区分

Python 的数据类型还可以从是否包含其他对象的角度分为**容器类型**和**原子类型**。容器类型能够存储其他对象的引用，前面讲的所有组合数据类型都是容器类型。原子类型只表示单个值，无法包含其他对象，包括整数、浮点数、布尔值等。

```python
# 容器类型：可包含其他对象
container = [1, "two", [3, 4], {"a": 5}]
print(len(container))  # 4，包含四个元素

# 原子类型：表示单个值
atom = 42
text = "hello"         # 字符串虽是序列，但是原子性的不可分割单元
```

容器类型的元素是通过引用关联的，这意味着容器本身只保存指向元素的引用，而非元素本身。把一个列表放进另一个列表时，外层列表保存的是内层列表的引用，修改内层列表会影响到外层列表看到的值。这一机制是后续嵌套结构和浅拷贝问题的基础。

## 4.1.8 空组合对象的布尔值均为 False

在布尔上下文中（如 if 条件、while 循环），空组合对象都被判定为 False。这包括空列表 `[]`、空元组 `()`、空字典 `{}` 和空集合 `set()`。只要组合对象中含有一个或多个元素，布尔值就为 True。这一特性让你可以用简洁的写法判断容器是否为空，无需显式比较长度。

```python
# 空组合对象为 False
empty_list = []
empty_tuple = ()
empty_dict = {}
empty_set = set()

print(bool(empty_list))    # False
print(bool(empty_tuple))   # False
print(bool(empty_dict))    # False
print(bool(empty_set))     # False

# 非空组合对象为 True
print(bool([0]))           # True，含一个元素
print(bool(""))            # False，空字符串也是空序列
print(bool(" "))           # True，含一个空格字符
```

实际开发中，判断列表或字典是否为空时，推荐直接写 `if data:` 而不是 `if len(data) > 0:`，前者更简洁也更符合 Python 风格。

```python
queue = []
if not queue:
    print("队列为空，暂无待处理任务")
# 输出：队列为空，暂无待处理任务
```

## 4.1.9 组合对象的长度获取

`len()` 是内置函数，返回组合对象中元素的个数。对于序列类型，它返回元素数量；对于字典，它返回键值对数量；对于集合，它返回元素数量。`len()` 在所有组合类型上的调用方式完全一致，这是 Python 统一接口设计的体现。

```python
print(len([1, 2, 3]))            # 3，列表长度
print(len("hello"))              # 5，字符串长度
print(len({"a": 1, "b": 2}))     # 2，字典键值对数
print(len({1, 2, 3, 3}))         # 3，集合去重后的元素数
print(len(range(0, 10, 2)))      # 5，range 生成的元素数
```

`len()` 的时间复杂度是 O(1)，因为所有组合类型内部都维护了长度信息，调用时直接返回，无需遍历统计。在循环条件或频繁判断中可以放心使用。

## 4.1.10 成员检查运算符

`in` 和 `not in` 是两个成员检查运算符，适用于所有组合类型。对序列类型（列表、元组、字符串），它们检查某个值是否作为元素存在。对字典，它们检查某个键是否存在而非值。对集合，它们检查某个元素是否存在。运算结果为布尔值。

```python
# 序列类型的成员检查
letters = ["a", "b", "c"]
print("b" in letters)        # True
print("z" not in letters)    # True

text = "hello"
print("ell" in text)         # True，字符串支持子串检查

# 字典的成员检查：检查键
config = {"host": "localhost", "port": 8080}
print("host" in config)      # True，键存在
print("localhost" in config) # False，值不参与检查

# 集合的成员检查
tags = {"python", "java", "go"}
print("python" in tags)      # True
```

不同类型的成员检查性能差异很大。列表和元组是线性扫描，时间复杂度为 O(n)。字典和集合基于哈希表，时间复杂度为 O(1)。当需要频繁判断某个值是否存在时，应优先使用集合而非列表。

## 4.1.11 迭代协议支持

所有组合类型都支持迭代协议，可以被 for 循环直接遍历。序列类型按元素顺序迭代，字典默认迭代键（可用 keys、values、items 方法改变），集合按内部存储顺序迭代。这种统一的迭代能力是 Python 数据处理的基础，让你可以用同一套 for 循环语法处理不同类型的数据。

```python
# 序列迭代
for item in [10, 20, 30]:
    print(item, end=" ")
# 输出：10 20 30
print()

# 字典迭代（默认迭代键）
for key in {"a": 1, "b": 2}:
    print(key, end=" ")
# 输出：a b
print()

# 字典迭代键值对
for key, value in {"a": 1, "b": 2}.items():
    print(f"{key}={value}", end=" ")
# 输出：a=1 b=2
print()

# 集合迭代
for elem in {100, 200, 300}:
    print(elem, end=" ")
print()
```

除了 for 循环，所有可迭代对象还可以传给 `list()`、`tuple()`、`set()` 等构造函数进行类型转换，或者用 `sum()`、`max()`、`min()` 等内置函数进行聚合运算。这种统一的迭代接口让组合类型之间可以方便地相互转换。

## 4.1.12 比较运算的逐元素比较规则

组合类型之间可以用 `==`、`!=`、`<`、`>` 等运算符进行比较，规则因类型而异。序列类型采用逐元素比较，从第一个元素开始一一对照，遇到不同就返回结果，全部相同则长度长的更大。字典的比较是检查两个字典的键值对是否完全相同，只支持 `==` 和 `!=`，不支持大小比较。集合的比较支持子集和超集关系判断。

```python
# 序列逐元素比较
print([1, 2, 3] == [1, 2, 3])    # True，元素完全相同
print([1, 2, 3] < [1, 2, 4])     # True，第三个元素 3 < 4
print([1, 2] < [1, 2, 3])        # True，前两个相同，短的更小
print((1, 2, 3) == [1, 2, 3])    # False，类型不同不相等

# 字典比较：只支持相等判断
print({"a": 1} == {"a": 1})      # True
print({"a": 1} == {"a": 2})      # False
# print({"a": 1} < {"a": 2})     # TypeError: '<' not supported

# 集合比较：子集与超集
print({1, 2} < {1, 2, 3})        # True，{1,2} 是 {1,2,3} 的真子集
print({1, 2, 3} > {1, 2})        # True，{1,2,3} 是 {1,2} 的真超集
print({1, 2} <= {1, 2})          # True，子集包含相等情况
```

序列的大小比较有实际用途，例如按字典序排列单词、按优先级排序任务列表。比较时要求两个序列的对应元素类型兼容，整数和字符串之间无法比较，会抛出 TypeError。

## 4.1.13 身份比较与内容比较的区别

`is` 运算符比较两个对象的身份，即它们是否指向内存中的同一个对象。`==` 运算符比较两个对象的内容是否相等。对于组合类型，这两个运算符经常给出不同结果，理解它们的区别能避免隐蔽的 bug。

```python
# 内容相同但身份不同
a = [1, 2, 3]
b = [1, 2, 3]
print(a == b)    # True，内容相同
print(a is b)    # False，是两个不同的列表对象

# 同一个对象的两个引用
c = a
print(a is c)    # True，c 和 a 指向同一个列表
print(a == c)    # True，内容当然也相同

# 修改一个引用会影响另一个
c.append(4)
print(a)         # [1, 2, 3, 4]，a 也变了，因为 a 和 c 是同一个对象
print(b)         # [1, 2, 3]，b 不受影响，因为是独立对象
```

日常编程中判断两个容器内容是否一致，应该用 `==`。`is` 主要用于判断是否为 None，或者确认两个变量是否引用同一对象（例如在调试共享引用问题时）。把 `is` 误用为 `==` 会导致一些内容相同但身份不同的对象被判定为不相等。

## 4.1.14 组合对象的嵌套结构

组合类型的元素可以是任意类型，包括其他组合类型，这就形成了嵌套结构。列表可以包含字典，字典的值可以是集合，集合的元素可以是元组，各种类型可以自由组合。嵌套结构在表达复杂数据时非常常见，例如一个用户列表中每个用户是一个字典，字典中又包含标签列表和配置字典。

```python
# 列表中嵌套字典
users = [
    {"name": "alice", "tags": ["admin", "active"]},
    {"name": "bob", "tags": ["user"]},
    {"name": "carol", "tags": ["user", "vip"]}
]

# 字典中嵌套列表和字典
system = {
    "servers": ["web-01", "web-02", "db-01"],
    "config": {"timeout": 30, "retries": 3},
    "ports": {80, 443, 8080}
}

print(users[0]["name"])         # alice
print(system["config"]["timeout"])  # 30
print(system["servers"][1])     # web-02
```

嵌套结构没有层数限制，但层数过多会让代码难以阅读和维护。实际开发中，嵌套超过三层时通常考虑用数据类或自定义对象来组织，以提升可读性。

## 4.1.15 嵌套结构的索引链式访问

访问嵌套结构中的深层元素，需要把索引或键按层级顺序串联起来。对于列表用方括号加索引，对于字典用方括号加键，每一层访问返回下一层对象，再继续索引。这种链式访问写法直观地反映了数据的层级关系。

```python
# 多层嵌套的链式访问
data = {
    "departments": [
        {"name": "研发", "members": ["张三", "李四"]},
        {"name": "市场", "members": ["王五"]}
    ]
}

# 取第一个部门的第二个成员
print(data["departments"][0]["members"][1])  # 李四

# 取第二个部门的名称
print(data["departments"][1]["name"])        # 市场

# 列表嵌套列表的链式访问
matrix = [
    [1, 2, 3],
    [4, 5, 6],
    [7, 8, 9]
]
print(matrix[1][2])  # 6，第二行第三列
```

链式访问的每一层都依赖前一层的返回值，如果中间某一层不存在或越界，整个表达式会抛出 KeyError 或 IndexError。对于来源不可靠的数据（如网络接口返回的 JSON），应该逐层检查或使用字典的 `get()` 方法配合默认值，避免一层缺失导致整个访问链崩溃。

```python
# 安全的链式访问：逐层 get 兜底
value = data.get("departments", [{}])[0].get("members", ["未知"])[1]
print(value)  # 李四
```

掌握了组合类型的分类体系和通用特性后，下一节将深入序列类型（列表与元组）共有的操作细节，从索引、切片到拼接、比较，逐一讲解这些日常编程中使用频率最高的操作。

## 练习题

### 第 1 题：解释可变类型与不可变类型的区别

请说明 Python 中列表和元组在可变性上的核心差异，并举例说明这种差异带来的实际影响。

::: details 参考答案
列表是可变类型，创建后可以在原对象上增删改元素，对象的内存地址保持不变。元组是不可变类型，创建后长度和每个位置的元素引用都固定，无法修改。

```python
lst = [1, 2, 3]
print(id(lst))
lst.append(4)
print(id(lst))  # 地址不变

t = (1, 2, 3)
# t[0] = 10  # TypeError
```

实际影响体现在三个方面。元组可以作为字典键和集合元素，列表不行。元组在多线程环境下天然安全，无需加锁。元组向调用方传递了"这个值不会被改动"的明确信号。
:::

### 第 2 题：根据需求选择合适的数据类型

针对以下三种场景，分别选择最合适的 Python 组合数据类型并说明理由。场景一：存储一个班级 50 名学生的姓名，需要按学号顺序访问。场景二：根据商品编号查询商品价格。场景三：统计一篇文章中出现的所有不同单词。

::: details 参考答案
```python
# 场景一：列表
students = ["张三", "李四", "王五"]

# 场景二：字典
prices = {"A001": 12.5, "A002": 8.0}

# 场景三：集合
words = {"hello", "world", "python"}
```

场景一用列表，因为按位置顺序访问是序列类型的强项。场景二用字典，键值映射是字典的核心能力，O(1) 查找。场景三用集合，自动去重和 O(1) 成员判断是集合的专长。
:::

### 第 3 题：分析可哈希性对字典键的影响

下面的代码尝试用一个包含列表的元组作为字典键，会发生什么？请解释原因并给出修正方案。

```python
bad_key = (1, [2, 3])
d = {bad_key: "value"}
```

::: details 参考答案
代码会抛出 `TypeError: unhashable type: 'list'`。元组本身不可变，但当它包含可变元素时，哈希值依赖元素哈希值，列表的哈希值会随内容变化而失效，导致整个元组不可哈希。

修正方案是把内层列表也改成元组：

```python
good_key = (1, (2, 3))
d = {good_key: "value"}
print(d[(1, (2, 3))])
```

全不可变元素的元组可哈希，能作为字典键。这一限制背后的原理是哈希表结构，键的哈希值在其生命周期内必须保持稳定。
:::

### 第 4 题：项目练习题（命令行任务管理器）

命令行任务管理器需要存储多个任务，每个任务包含名称、状态、优先级。请选择合适的组合数据类型来组织这些数据，并初始化示例数据。考虑后续需要按任务名查找、按状态筛选等操作。

::: details 参考答案
```python
# 用列表存储任务，每个任务是一个字典
tasks = [
    {"name": "写文档", "status": "todo", "priority": 2},
    {"name": "修复 Bug", "status": "todo", "priority": 1},
    {"name": "评审代码", "status": "done", "priority": 3},
]

# 按名称查找
def find_by_name(task_list, name):
    for task in task_list:
        if task["name"] == name:
            return task
    return None

print(find_by_name(tasks, "修复 Bug"))
```

外层用列表保持插入顺序和按位置访问能力，每个任务用字典存储字段，方便按字段名访问和扩展。这种"列表嵌套字典"的结构是任务管理器最常见的数据组织方式，兼顾了顺序性和字段灵活性。
:::

## 常见错误

**错误 1 · `TypeError: unhashable type: 'list'`**

原因:把列表作为字典的键或集合的元素。列表是可变类型，内容可随时改变，哈希值无法保持稳定，Python 禁止其进入哈希表结构。

解决:改用元组或 frozenset 作为键。如果数据本来就是位置序列，用 `tuple(lst)` 转换后再作为键；如果是去重集合，用 `frozenset(s)` 转换。

**错误 2 · `a is b` 返回 `False`，但 `a == b` 返回 `True`**

原因:把 `is` 当作 `==` 使用。`is` 比较对象的身份（内存地址），`==` 比较内容。两个独立创建的列表即使内容完全相同，也是不同的对象，`is` 返回 `False`。

解决:判断内容是否相等用 `==`。`is` 仅用于判断 `None`、`True`、`False` 或确认两个变量是否引用同一对象。

**错误 3 · `TypeError: unhashable type: 'list'`（元组场景）**

原因:元组本身不可变，但当元组包含列表等可变元素时，其哈希值依赖内部元素的哈希值，可变元素的存在导致整个元组不可哈希，无法作为字典键。

解决:把元组内的可变元素也改为不可变类型，例如把内层列表改成元组 `(1, (2, 3))`。需要嵌套可变数据作为键时，重新设计数据结构，用字符串或整数等可哈希类型作为键。
